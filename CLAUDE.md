# rules_openmeter

Bazel rules for a hermetic per-test OpenMeter (API server + sink worker) on
Kafka, ClickHouse and Postgres from rules_kafka, rules_clickhouse and rules_pg:
- `openmeter_server` + `openmeter_health_check`: OpenMeter against servers you declare (rules_itest);
- `openmeter_stack`: all four servers as one executable;
- `openmeter_test`: an `sh_test` macro with `om_*` helpers.

The binaries are extracted from the digest-pinned image ghcr.io/openmeterio/openmeter (two layers per platform); see DESIGN.md.

## Commit requirements

- All tests must pass before any commit with code changes: `bazel test //tests/...`. Run `.github/consumer/check.sh <scratch dir>` too when the extension, `MODULE.bazel`, `.gitattributes`, the README's Installation section or the public API changes.
- All documentation (`README.md`, `DESIGN.md`, `CLAUDE.md`) must be updated to reflect any code changes before committing.
- The `OPENMETER_*` variable names are a stable interface. Add new ones; don't rename or remove.
- The README's Installation overrides must match `MODULE.bazel`'s (the consumer check compares them).
- Every commit message ends with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never commit `bazel-*`, `MODULE.bazel.lock`, `__pycache__`.

## Key concepts

- **Clean environment.** viper's `AutomaticEnv` turns any environment variable into a config override, so OpenMeter runs with `PATH`, `HOME`, `TMPDIR`, `LANG` only.
- **Readiness.** API: `GET /api/v1/meters` 200 (after migrations, namespace + topic provisioning, meter loading). Sink: its `kafka partition assignment` record for `om_<ns>_events` + `/healthz/ready`. The sink starts after the API (it reads meters from Postgres).
- **Ports.** Three free ports (API, server telemetry, sink telemetry); "address already in use" in a log means a retry with new ports (3 attempts).
- **rules_pg's pgdata.** It is `$TEST_TMPDIR/pgdata` whatever the server's name; the stack runs Postgres with its own `TEST_TMPDIR`.
- **Termination.** OpenMeter requires `termination.checkInterval >= 1s`; `propagationTimeout: 0s` makes SIGTERM fast.
